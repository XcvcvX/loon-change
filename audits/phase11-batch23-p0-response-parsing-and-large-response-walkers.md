# Phase 11 batch 23 — P0 response parsing and large-response walker audit

## Scope

- Jingdong: `scripts/jingdong/jd.js`, generated by `tools/optimize_jd.py`
- Spotify: `scripts/spotify/spot-NoSearchAd.js`, `scripts/spotify/spot-NoScrollAd.js`, generated by `tools/integrate_spotify.py`
- YouTube: response triggers in `allAdRewrite.plugin`, normalized by `tools/apply_local_overrides.py`
- Cross-app audit: Taobao, Pinduoduo, Meituan, Didi, Baidu Map and Amap active response handlers
- Regression coverage: Jingdong, Spotify integration, local overrides, optimization manifests

## Findings and changes

### Jingdong — remove per-element callback dispatch

The high-frequency welcome-home, custom-surface, delivery and order response branches used a generic in-place compactor with predicate callbacks. Replace those callbacks with a mode-dispatched indexed walker. Each array selects its mode once, then walks by index with a cached initial length and stable in-place writes. The order branch also uses a dedicated service-card walker; profile-floor cleanup uses a direct indexed loop rather than a replacement array.

The allowlist predicates that were only used by those callbacks are now expressed as direct scalar comparisons. The existing single JSON parse, supported-route pre-parse guard and lazy stringify behavior remain unchanged. Null entries, stable ordering, optional welcome argument handling, nested service-card removal and property deletion are covered by runtime tests.

### Spotify — avoid field-array construction on large binary responses

The Search and Scroll protobuf scripts previously scanned once with a no-allocation preflight, then built an array of field metadata objects, per-field byte views, a mapped parts array and a reduced concatenation buffer before rebuilding the response.

Keep the no-op preflight, but replace the second stage with a depth-limited range walker. It carries offsets into the original `Uint8Array`, rewrites the first matching ad field to unknown field 1000, and reconstructs only the changed ancestor ranges. The old `parseFields`, `concat`, `fields.map` and `parts.reduce` paths are removed. Search retains its existing 12,000-byte threshold; Scroll retains its field-30 match. No-op responses still create no subarray views.

### YouTube — remove confirmed duplicate response handling

The R-Store YouTube response trigger previously covered `guide` and `account/get_setting`, while the Maasea YouTube response handler was already narrowed to exactly those endpoints. Narrow the R-Store matcher to browse, next, player, search, reel watch sequence and get-watch. Guide and account settings continue to be handled by Maasea; all other handlers and their existing arguments remain in place. The override is idempotent and fails closed if the reviewed matcher inventory becomes ambiguous.

## Cross-app audit — intentionally unchanged paths

- **Taobao:** supported-route classification occurs before the one top-level JSON parse; changed responses serialize lazily. Splash traversal already caches section/item references and lengths.
- **Pinduoduo:** homepage handling is already consolidated to one response handler; order ad cleanup is implemented with native response JSON deletion rather than a second JavaScript JSON parser. No additional body parser was introduced.
- **Meituan:** ordinary routes use one top-level parse. The additional parse on `/assistant/getAppClientHornConfig` is necessary because `data` itself is JSON text and the script modifies its nested `skills` object. Tests explicitly preserve this behavior.
- **Didi:** seven response-array filters have already been converted to specialized callback-free compaction and direct property loops.
- **Baidu Map:** the active local response trigger is the binary `qt=ads` route. Header metadata caching, target-only byte views, multi-segment reconstruction and single-encode response assembly are already covered by binary regression tests.
- **Amap:** the active local response script already uses specialized in-place compaction modes and caches nested `routeInfo`/`routePlan` references. Remaining small loops operate over fixed key lists or route-specific structures; no broad recursive walker was added without evidence that it removes repeated work.

## Validation boundary

CI validates generated runtimes, optimizer idempotence/fail-closed behavior, output-preservation invariants, protobuf byte-order/length behavior, no-op allocation behavior and YouTube trigger non-overlap. These are source-level and runtime-harness checks. They do not establish measured iPhone CPU, battery, memory, temperature or end-to-end latency improvements; no device-level percentage is claimed.
